## 학습결과

학습에 사용한 하이퍼파라미터는 맨 마지막에 적어두었습니다.

{% include chart.html src="/assets/data/lunarlander.json" caption="DQN A2C PPO 학습결과 비교" %}

| Algorithm | Seeds | Normalized AUC | Final return | Steps to 200 | Reached |
|---|---|---|---|---|---|
| A2C | 5 | -61.1 [-113.5, -11.2] | -123.3 [-130.1, -113.0] | 1,000,000 [840,000, 1,000,000] | 1/5 |
| DQN | 5 | 161.2 [134.7, 182.1] | 255.8 [226.5, 271.7] | 233,333 [166,667, 340,000] | 5/5 |
| PPO | 5 | 144.7 [133.9, 170.7] | 279.1 [276.7, 282.5] | 226,667 [200,000, 253,333] | 5/5 |

IQM [95% bootstrap CI]

똑같은 시드 5개에서 학습을 진행했습니다. 

- Normalized AUC : 학습곡선 아래 면적을 step수로 나눈 값
- Final return : 마지막 평가 3개의 평균 값
- Steps to 200 : 200점에 도달하기까지 걸린 step(A2C에서 1,000,000의 값이 나온 것은 학습 마지막까지 도달하지 못했다는 의미)
- Reached : LunarLander환경을 해결했다고 보는 기준선인 200에 도달한 시드가 몇 개인지 체크합니다.

DQN이 가장 높은 AUC를 기록하여 샘플 효율이 좋다고 볼 수 있지만 대부분의 신뢰구간이 겹치기 때문에 큰 차이는 없다고 보입니다.
PPO의 Final Return이 가장 높았고 그래프를 살펴보아도 시드별 편차가 가장 작았고 학습 중에 성능이 붕괴되는 현상도 가장 작았습니다.

A2C는 학습이 전반적으로 잘 되지 않았습니다. 그래프를 살펴보게 되면 중간 중간 정책이 개선되는 것 같이 보이지만 최종적으로 정책이 붕괴된 채 회복하지 못하고 학습이 종료되었습니다.
A2C의 학습이 잘 되지 않은 이유는 다음 글에서 다루도록 하겠습니다.

## 하이퍼파라미터

### 공통 설정 (LunarLander-v3)

| 항목 | 값 |
| --- | --- |
| 학습 예산 (`total_timestep`) | 1,000,000 env step |
| 병렬 환경 수 (`num_envs`) | 8 |
| 네트워크 (`hidden`) | MLP [64, 64] |
| 할인율 (`gamma`) | 0.99 |
| 평가 주기 (`eval_interval`) | 20,000 step |
| 평가 에피소드 (`eval_episodes`) | 10 |
| 평가 seed (`eval_seed`) | 10000 (학습 seed와 분리) |

### 알고리즘별 설정

| 항목 | A2C | PPO | DQN |
| --- | --- | --- | --- |
| 출처 | SB3 rl-zoo | SB3 rl-zoo | SB3 (araffin/dqn-LunarLander-v2) |
| 학습률 | 0.00083 (고정) | 0.0003 (고정) | 0.0007 |
| 활성화 함수 | tanh | ReLU | ReLU |
| `max_grad_norm` | 0.5 | 0.5 | 10.0 |
| rollout 길이 (`num_steps`) | 5 | 1024 | – |
| `gae_lambda` | 1.0 | 0.98 | – |
| `ent_coef` | 0.00001 | 0.01 | – |
| `num_epochs` / `minibatch_size` | – | 4 / 64 | – |
| `clip_coef` | – | 0.2 | – |
| advantage 정규화 | ✗ | ✓ | – |
| `buffer_size` / `batch_size` | – | – | 100,000 / 128 |
| ε (시작 → 끝, 감소 step) | – | – | 1.0 → 0.05, 80,000 step |
| `learning_starts` | – | – | 1,000 |
| `train_freq` / `target_update_freq` | – | – | 2 / 250 |

A2C만 활성화 함수를 tanh을 쓴 이유는 CartPole로 돌렸을 때 ReLU를 쓸 때보다 tanh을 쓸 때 학습이 더 잘 됐어서 tanh을 사용했습니다.
